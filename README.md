# Chatbot LLM - Full Stack Application

A modern, responsive chatbot application with React frontend and Node.js backend, integrated with Ollama for LLM capabilities.

## Features

- 🤖 Modern chat interface with message bubbles
- � User authentication and session management
- 💬 Real-time typing indicators and loading states
- 🎨 Clean Material-UI design with responsive layout
- 📱 Fully responsive design for all devices
- 🔍 Conversation search functionality
- 📂 Conversation history organized by date (Today, Previous 7 Days, Earlier)
- ✏️ Rename and delete conversations
- 📤 Share conversations via email, copy link, or QR code
- ⚡ Fast and lightweight with local LLM integration
- 🔧 Backend server with Ollama integration

## Scope of the Chatbot Assistant

This chatbot assistant is designed to provide intelligent, context-aware conversational AI capabilities for various use cases including:

- **General Q&A**: Answer questions on a wide range of topics using the power of Large Language Models
- **Task Assistance**: Help users with writing, coding, research, and problem-solving tasks
- **Information Retrieval**: Provide quick access to information and explanations
- **Creative Support**: Assist with creative writing, brainstorming, and idea generation
- **Learning Aid**: Support educational purposes by explaining concepts and providing examples
- **Personal Assistant**: Help with daily tasks, scheduling, and organization

The chatbot operates entirely locally using Ollama, ensuring privacy and data security while providing fast, responsive interactions.

## Inputs

The chatbot accepts the following inputs:

- **User Messages**: Text-based questions, prompts, or commands entered through the chat interface
- **Conversation Context**: Previous messages in the current conversation to maintain context and continuity
- **User Profile**: Email and name for session management and personalization (optional)
- **Conversation History**: Access to past conversations for reference and continuity
- **Search Queries**: Keywords or phrases to search through conversation history

## Outcomes

When interacting with the chatbot, users can expect:

- **Intelligent Responses**: Contextually relevant answers generated by the LLM
- **Natural Conversations**: Human-like dialogue flow with appropriate tone and style
- **Quick Turnaround**: Fast response times due to local LLM processing
- **Structured Information**: Well-formatted responses with clear explanations
- **Code Examples**: When relevant, the chatbot can provide code snippets and examples
- **Multiple Perspectives**: Balanced viewpoints on complex topics
- **Follow-up Suggestions**: Related questions or topics to explore further

## Limitations

The chatbot has the following limitations:

- **Knowledge Cutoff**: The LLM's knowledge is limited to its training data and may not include very recent information
- **Accuracy**: Responses may occasionally contain inaccuracies or hallucinations
- **Context Window**: Limited memory of previous messages in long conversations
- **Local Processing**: Performance depends on local hardware capabilities
- **Model Dependency**: Quality of responses depends on the selected Ollama model
- **No Internet Access**: Cannot browse the web or access real-time information
- **No File Processing**: Cannot directly process or analyze uploaded files
- **Language Support**: Primarily optimized for English, though other languages may work depending on the model

## Architecture Flow

The chatbot follows a client-server architecture with the following flow:

```
User Interface (React Frontend)
         ↓
    HTTP Request
         ↓
Backend Server (Express.js)
         ↓
    Ollama API Call
         ↓
Local LLM (Ollama)
         ↓
    LLM Response
         ↓
Backend Processing
         ↓
HTTP Response
         ↓
User Interface Display
```

**Components:**

1. **Frontend (React)**: Handles user interactions, displays messages, manages conversation state
2. **Backend (Express.js)**: Acts as API gateway, handles authentication, communicates with Ollama
3. **Ollama**: Local LLM runtime that processes prompts and generates responses
4. **Browser Storage**: Stores conversation history and user session data

## Step-by-Step Process

### 1. User Authentication
- User enters email and name (optional)
- Session is created and stored in browser localStorage
- User profile is maintained for the session duration

### 2. Message Submission
- User types a message in the input field
- Message is added to the local conversation state
- Frontend sends the message to the backend via HTTP POST request

### 3. Backend Processing
- Backend receives the message and conversation context
- Formats the message for Ollama API
- Sends request to Ollama's local API endpoint

### 4. LLM Processing
- Ollama receives the prompt with conversation history
- LLM processes the input using its trained model
- Generates a contextually appropriate response

### 5. Response Handling
- Backend receives the LLM response
- Processes and formats the response
- Sends it back to the frontend via HTTP response

### 6. Display & Storage
- Frontend receives the response
- Displays the message in the chat interface
- Saves the conversation to localStorage for persistence
- Updates conversation history in the sidebar

## How It Stores History

The chatbot uses browser localStorage for conversation persistence:

- **Storage Location**: Browser's localStorage API
- **Data Structure**: Conversations stored as JSON objects with metadata
- **Organization**: Conversations grouped by time periods (Today, Previous 7 Days, Earlier)
- **Metadata**: Each conversation includes:
  - Unique ID
  - Title (auto-generated from first message)
  - Timestamp
  - Message history (user and bot messages)
  - User profile information

**Storage Features:**

- **Persistence**: Conversations survive browser restarts
- **Search**: Full-text search across all conversations
- **Management**: Rename, delete, and share conversations
- **Privacy**: Data stored locally on user's device, not sent to external servers

## Why It Uses LLM

The chatbot leverages Large Language Models (LLMs) for several key reasons:

- **Natural Language Understanding**: LLMs excel at understanding human language in all its complexity
- **Context Awareness**: Can maintain context across multi-turn conversations
- **Knowledge Base**: Access to vast amounts of information from training data
- **Flexibility**: Can handle a wide variety of tasks without specific programming
- **Generative Capabilities**: Can create original content, not just retrieve pre-written answers
- **Reasoning**: Can perform logical reasoning and problem-solving
- **Adaptability**: Adjusts responses based on user's level of expertise
- **Continuous Improvement**: LLMs can be updated with new models for better performance

**Why Ollama Specifically:**

- **Privacy**: Runs entirely locally, no data leaves your machine
- **Cost**: No API fees or subscription costs
- **Performance**: Fast inference on local hardware
- **Customization**: Can use various open-source models
- **Offline Capability**: Works without internet connection
- **Control**: Full control over model selection and configuration

## LLM Integration Note

**Important:** This project was initially designed to work with LMStudio, but due to connection issues with LMStudio, we have switched to using **Ollama** as the LLM provider. Ollama provides a more stable and reliable connection for local LLM inference.

If you prefer to use LMStudio instead, you would need to modify the backend API endpoint in `backend/server.js` to connect to LMStudio's API instead of Ollama's.

## Working Process

### Step 1: Start Ollama Server

Ensure Ollama is installed and running on your system:
```bash
# Start Ollama (if not already running)
ollama serve
```
or
```bash
# If the path ollama is not existing while running
export PATH="/c/Users/kodal/AppData/Local/Programs/Ollama:$PATH"
# Start Ollama (if not already running)
ollama serve
```

Pull a model if you haven't already:
```bash
# Example: Pull Llama 3 model
ollama pull llama3
```

### Step 2: Start the Backend Server

Navigate to the backend directory and start the server:
```bash
cd backend
npm start
```

The backend server will run on `http://localhost:5000`

### Step 3: Start the Frontend Application

In a new terminal, navigate to the project root and start the React app:
```bash
npm start
```

The frontend will open in your default browser at `http://localhost:3000`

### Step 4: Use the Application

1. **Sign In**: Click on the avatar icon in the top-right corner and enter your email and name
2. **Start Chatting**: Type your message in the input field and press Enter or click the Send button
3. **Manage Conversations**: 
   - Create new chats using the "New Chat" button
   - Access conversation history from the sidebar
   - Search conversations using the search icon
   - Rename or delete conversations using the menu (three dots)
   - Share conversations via email, copy link, or QR code

## Backend Configuration

The backend server (`backend/server.js`) connects to Ollama using the following configuration:

- **Ollama Endpoint**: `http://localhost:11434/api/chat`
- **Backend Port**: `5000`
- **Model**: Configured in the backend (default: llama3)

To change the model, edit the `model` parameter in `backend/server.js`.

## Troubleshooting

### Backend Connection Issues
- Ensure Ollama is running: Check if `http://localhost:11434` is accessible
- Verify the backend server is running on port 5000
- Check browser console for CORS errors

### Ollama Model Issues
- Ensure you have pulled a model: `ollama pull <model-name>`
- Check Ollama logs: `ollama logs`

### Frontend Issues
- Clear browser cache and localStorage
- Check that all dependencies are installed
- Verify React development server is running on port 3000
